> 建立日期:2026-11-04。依据:«字节跳动 Agent 实践手册»(108 页)全文分析(全文 md 转写版:
> [agent-practice-manual.md](agent-practice-manual.md)),对照本仓库
> 封面/视频剪辑/总助手三个会话智能体与 .31 服务端链路的真实运行证据(1103 视觉路由、
> 1104 抠图死循环、1029 DeepSeek 503 等事故)裁剪而成。
> 性质:开发借鉴标准——手册的**方法论**采纳,**工具名**(豆包/扣子/飞书/ByteMQ 等)不迁移。
> 使用方式:新写/修改会话智能体(SKILL.md、会话桥、模型供给、工具面)时对照第 4 节逐条自查;
> 第 3 节差距表用于排期,标注「待裁决」的条目需用户点头后才动工。

## 1. 手册可迁移的六条主轴

1. **分层架构**:感知层(输入/上下文采集)→推理层(模型+规划)→执行层(工具/API),层间
   通信要有错误重试与容错;Agent 不是孤立工具,必须与既有系统深度集成。
2. **场景聚焦,问题驱动**:一个 Agent 解决一个高频痛点,拒绝大而全;上线即产生可量化价值。
3. **模型分级配岗**:按「任务复杂度-响应速度要求-成本」三要素选型——简单任务用规则/轻量
   模型,复杂推理用 thinking 模型;模型能力有波动,关键链路必须配**多模型 fallback** 与
   **能力监测**。
4. **混合决策**:规则能定的不劳烦大模型(快且准),复杂判断交给模型;两者结合平衡效率与准确性。
5. **数据闭环,持续迭代**:用户反馈→数据监测→模型/提示词优化的闭环;迭代需求按
   「业务价值-实现成本-紧急程度」排序,双周小迭代+周期性复盘。
6. **风险前置**:大模型不稳定/性能瓶颈/用户不接受/流程不匹配/合规——五类风险各有预案
   (fallback、压测+降级、分段推广+效果可视化、流程调研+自定义配置、数据分级+内容审核)。

## 3. 差距清单(按优先级,★=需用户裁决/外部配合)

1. **T1 模型分级配岗**(已立为标准,回溯适用):推理编排必须用旗舰级模型;专用小模型
   (本地 VL/量化档)只承担**单步感知任务**(看图出描述、OCR、裁剪建议),禁止承担多步
   工具编排。判据=响应里出现 tool_use 即为编排,编排段模型不得降级。
2. **T2 声明式 fallback**:技能正文为关键外部依赖写明「主选→备选1→备选2,每个只试一次,
   全失败如实上报」,替代模型即兴乱试(1104 bria/silueta 全崩才撞对 isnet)。
3. **T3 工具输出先验证再消费**:HTTP 状态+内容魔数/结构校验,不合规不落盘、错误原文上屏。
   封面 SKILL 已落地;视频剪辑/总助手的 SKILL 同步补齐(客户端可做)。
4. **T4 超时与降级红线**:任何同步外部调用必须设显式超时;超时/失败走降级路径并在界面
   有可见反馈,禁止 >30s 静默(1103 读取中 5 分钟条款)。服务端链路随 vision 规格验收,
   客户端宿主桥已有 30s 默认超时,保持。
5. **T5 场景聚焦**:一个智能体一个主场景;能力按装位隔离(cover-skills/film-agent-home/
   creation-skills 互不相通已是实践),新能力先问「归哪个场景」再动工。
6. **T6 交互纪律**(固化既有守规):改完一句话汇报;需要决策就问,不自作主张;上下文
   引用(@图层/@素材)优先于让用户重复描述。
7. ★**T7 会话冒烟用例集**:每个智能体维护 5-10 条典型任务+验收判据(如「抠图任务:产物
   为合法 PNG 且进素材区;失败时报错误原文」),SKILL/桥改动后跑一遍。纯守规无测试是
   当前最大质量缺口;建法(脚本化 vs checklist)待裁决。
8. ★**T8 轻量运营指标**:clientLog 增量统计 turn 成功率、turn 失败原因分类(上游 5xx/
   超时/工具错误/中止)、每会话工具调用数。只进本地日志不外发(合手册 §6 最小必要)。
   是否做、做到什么粒度待裁决。
9. ★**T9 营销文案合规提示**:封面/运营场景 SKILL 增补「营销文案禁绝对化用语(最好/第一/
   国家级等)、禁虚假功效宣称」一段(手册 §10.3.2 提示工程条款的裁剪)。是否加待裁决。
10. **T10 契约先行**(固化):跨机(客户端↔.31↔comfygen)、跨会话(客户端会话↔服务端会话)
    改动,先出接口契约文档再实施(HARD-GATE 既有实践,vision-routing 规格为范例)。
11. **T11 批次迭代与复盘**(固化):批次提交+记忆文件记录事实/根因/修法(≈4F 复盘);
    新需求按「业务价值-实现成本-紧急程度」排序后进批次,不插队。
