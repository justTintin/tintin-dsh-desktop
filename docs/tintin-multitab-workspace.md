# 运营/媒体工具多 Tab 工作区（下一版本需求）

状态：**需求已裁决、排期下一版本**（2026-11-09 用户提出）。本文档是开工时的实现规格；本期未实施，任何代码都未改动。

## 需求背景

现状：运营工具（`dsh-tintin-ops-bundle/src/OpsApp.vue`）与媒体工具（`dsh-tintin-media-bundle/src/App.vue`）都是「卡片导航页 → 点卡片整页替换为工具详情 → 顶部『返回 ×× 工具』回导航」的单视图模式，详情有 KeepAlive 但**每卡只有一个实例**。

用户裁决的目标形态（2026-11-09，对齐浏览器 tab 栏）：像浏览器一样用 tab 承载工具页。

## 交互规格

1. **Tab 栏**：替换现在的「返回媒体工具 / 返回运营工具」页头条位置（页面顶部）。每个 tab = 图标(emoji) + 工具名，形态对齐浏览器 tab（第二参考图：favicon+标题+右侧 +）。
2. **最右侧「+」按钮**：点击回到该域的卡片导航界面（运营工具 / 媒体工具首页）。导航页不是 tab（或作为常驻特殊 tab，开工时定）。
3. **打开卡片 = 新建 tab**：从导航点任意卡片，开一个新 tab 并切换过去；已有 tab 不受影响。
4. **多 tab 共存切换**：tab 间点击切换，各自的界面状态、滚动位置、表单内容保持。
5. **相同卡片可多开**：同一功能卡可以同时开多个 tab，**各实例任务互不干涉**（如两个「仿爆款视频」同时跑不同任务、两个「产品资料」各自选不同产品编辑）。
6. 两个域（运营工具 / 媒体工具）各自一套 tab 栏，互不混排。

## 开工时必须裁决的技术点

按工程影响从大到小：

1. **实例隔离机制（本需求最大的工程量）**。现状多个工具域的 composable 是模块级单例（`useImitationVideo`、`useOpsProductLibrary` 等组合式函数内部 state 在模块作用域），同卡多开时所有 tab 实例会共享同一份业务状态 → 「互相不干涉」不成立。两条路线：
   - 路线 A：composable 工厂化——单例 state 改为 `createXxxState()` 工厂 + provide/inject 沿组件树注入，每 tab 一个独立 state。改动面=所有被多开卡消费的 composable 及其消费组件。
   - 路线 B：每 tab 独立 webview/iframe（强隔离，天然互不干涉），代价=桥通信改造、内存翻倍、与宿主 KeepAlive 体系脱节。
   - 需盘点媒体/ops 两包全部模块级单例 composable 清单后才能定量（先盘点后裁决）。
2. **KeepAlive key**：从卡片 id 改为 tab 实例 id（tab 关闭即销毁实例、中止其轮询/任务——关闭运行中任务的 tab 是否需要确认弹窗，需裁决）。
   - **保活数量上限（浏览器 discard 语义）**：Vue 3 KeepAlive 原生支持 `:max`（LRU——超出后销毁最久未用的实例，激活时重建）。建议 `:max` 钉一个值（如 6~8）控内存：tab 条可以很多，但只有最近 N 个实例真正保活，更早的切回时重置。与「状态不丢」验收存在张力——保活上限内不丢、超限重置，需用户裁决取舍。
3. **tab 持久化**：重启应用后是否恢复上次 tab 集（建议二期再做，一期先会话内有效）。
   - 浏览器 Session Restore 恢复的是「URL 列表」（重新加载），不是运行态快照——对应到我们是**恢复 tab 骨架（开了哪些工具）**，组件内状态（表单/结果）不跨重启；业务自持久化的除外（创作历史 localStorage 等照旧）。
4. **tab 上限与溢出**：建议软上限（如 12 个），溢出横向滚动；不设上限也可，仅溢出滚动。
   - 浏览器做法是 tab 缩窄（标题省略到最小宽再滚动），可选实现；一期直接横向滚动最简单。
5. **导航页形态**：「+」回导航页后，导航页本身是否占一个 tab 位（浏览器新标签页语义）或始终作为无 tab 的底层视图（现状语义）。
6. **组件归属**：tab 栏骨架组件放哪——两包独立不互依，公共组件各包持副本是既有先例（TButton / OtPickMaterialDialog 移植先例），tab 骨架同策略做副本，还是进 shared（shared 是纯 JS 叶子不塞 Vue 的先例）——需按副本先例处理。

## 参考浏览器模式的补充清单（2026-11-09 追问补全）

从浏览器交互逐项对照，分三档：**建议做**（低成本高价值）/ **裁决**（有取舍）/ **明确排除**（记录不做，防止开工时发散）。

### 建议（浏览器惯例，成本低）

- **per-tab 关闭钮 ×**：活动 tab 常显、非活动 hover 显（浏览器惯例）；**中键点击关闭**。
- **关闭后焦点给相邻 tab**（先右后左），不回导航页。
- **任务状态小标**：后台 tab 任务运行中/完成时，tab 上显示状态点（浏览器音频 tab 的喇叭图标语义）——后台跑任务的 tab 切走后回来一眼看到哪些跑完了。
- **右键菜单**：关闭其他 / 关闭右侧（浏览器标配，实现便宜）。
- **活动 tab 高亮**：底部主色下划线或整条亮底，与侧栏选中态风格一致。

### 裁决（浏览器有对应行为，但取舍真实存在）

- **关闭运行中/有未保存内容的 tab**：浏览器关闭有未提交表单的页会弹确认。对应规则建议：任务运行中→确认「中断并关闭」；表单 dirty（产品资料编辑未保存等）→确认丢弃；纯浏览态→直接关。dirty 判定需要各面板暴露（或一期从宽：只有任务运行中才拦）。
- **后台 tab 轮询节流**：浏览器对后台 tab 降 timer 频率。任务型轮询（拆解/上传/unified 轮询）切后台**必须继续**，纯 UI 刷新轮询（素材条 3 秒轮询先例）可降频或暂停——避免 10 个 tab × N 个轮询打满服务端。需要按轮询分类清单逐个标注「任务型（不停）/ UI 型（节流）」。
- **同卡多开的数据共享**：多开两个「产品资料」，只读数据（树/素材列表）重复请求×2——可选共享只读缓存 + 各 tab 私有编辑态（混合优化）；一期不共享（各自独立请求）更符合「互不干涉」，服务端压力可接受后再优化。
- **跨卡直达信号的映射**：现有切卡信号（媒体包 pendingMediaTool→视频去水印字幕、pendingStoryboard→仿视频等）在 tab 模式下变成「新开 tab 还是聚焦已有同工具 tab」——浏览器对应「链接打开新 tab vs 复用同站 tab」。建议：直达信号=聚焦已有该工具 tab，无则新开（避免直达链路开出重复 tab）。
- **侧栏入口与活动 tab 的关系**：左侧插件栏「媒体工具/运营工具」再点一次=回导航页还是聚焦最近 tab（浏览器任务栏图标=聚焦窗口语义）；侧栏高亮跟随所属域是否有活动 tab。
- **崩溃隔离**：Vue 实例路线下单 tab 组件抛错会沿组件树冒泡——每 tab 内容区加 errorCaptured 边界，崩一个 tab 不连累其他（webview 路线天然隔离，此项自动满足）。

### 排除（明确不做，防发散）

- **拖出成独立窗口 / 多窗口**：Electron 多窗口 + 桥多实例成本高，业务上无场景。
- **tab 拖拽重排、pin 固定 tab、hover 预览卡片**：锦上添花，一期不做（右键菜单都不含）。
- **误关恢复（Ctrl+Shift+T）**：依赖 tab 持久化，二期随会话恢复一并考虑。
- **键盘快捷键**（Ctrl+W 关闭 / Ctrl+Tab 切换 / Ctrl+数字跳转）：一期不做——Electron 全局快捷键面与宿主/上游冲突面未盘点，纯 UI 点击先行。
- **分屏**（Edge split screen）：无场景。

## 验收标准

- 同一卡片开两个 tab，分别发起任务（如两个仿视频拆解），进度/结果互不串扰。
- 切换 tab 不丢失任何表单/滚动/轮询状态；关闭 tab 后其轮询停止（无幽灵请求）。
- 「+」回导航页、点卡新开 tab、重复开同卡、切换、关闭全链路可用。
- 关闭运行中任务的 tab 有确认；后台 tab 的任务型轮询不受切换影响，UI 型轮询按节流策略降频。
- 后台 tab 任务完成有状态点提示；跨卡直达信号只聚焦/新开一个 tab，不产生重复。
